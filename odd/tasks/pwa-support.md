# PWA support for MeperPOS (iOS + Android)

Make the Next.js frontend installable as a Progressive Web App with iOS and Android support: manifest, app icons, a service worker with a safe cache lifecycle, and an install affordance for both platforms.

Branch: `feat/pwa-support`. Base: `53b2272` (`master`).
Authorized surfaces: `frontend/src/app/manifest.ts`, `frontend/src/app/layout.tsx`, `frontend/src/app/offline/**`, `frontend/src/components/pwa/**`, `frontend/src/hooks/useInstallPrompt.ts`, `frontend/src/lib/pwa.ts`, `frontend/src/lib/session.ts`, `frontend/public/sw.js`, `frontend/public/icons/**`, and the matching `*.test.ts(x)` files, plus this document.
Risk tier: high. A service worker is delivery/runtime surface for every installed client, is hard to undo once cached, and no jsdom test can prove real browser install behavior.

## Specs

- **S1 — PWA.** The user said: "hacemos a MeperPOS PWA". The frontend MUST be installable: a valid web app manifest (`name`, `short_name`, `start_url`, `scope`, `display: standalone`, `theme_color`, `background_color`) plus at least one 192px and one 512px icon, one of them `maskable`, and a registered service worker with a `fetch` handler (Chrome installability criteria).
- **S2 — iOS.** The user said: "le damos soporte para ios". iOS/WebKit MUST be able to install and run the app standalone: `apple-mobile-web-app-capable` and status-bar metadata, a 180×180 `apple-touch-icon`, and an install affordance that shows "Add to Home Screen" instructions, because WebKit never fires `beforeinstallprompt`. The installed app MUST be told apart from a browser tab so the UI does not offer an install that cannot happen.
- **S3 — Android.** The user said: "y android". Chromium MUST be able to install through the captured `beforeinstallprompt` event, and the install affordance MUST disappear once the app is already installed.
- **S4 — Isolated branch.** The user said: "crea una rama para esto". All of this work MUST live on `feat/pwa-support`, never on `master`.
- **S5 — Safe areas.** The owner asked for Fase 2 of `plan-08`: "Fase 2 + deuda" (2026-11-14). `viewport-fit: cover` makes every surface draw edge to edge, and only `MobileCartDrawer` and `MobileCartFloatingBar` compensate today. The mobile header, the slide-over drawer, the authenticated content column and the auth pages MUST each pay back `env(safe-area-inset-*)`, so no interactive content sits under a notch, a rounded corner or the home indicator. `env()` resolves to `0px` outside a notched standalone context, so the compensation is applied unconditionally and must not change desktop rendering.
- **S6 — Connection state.** The app MUST tell the operator whether it is online, driven by `navigator.onLine` and the `online`/`offline` events, without blocking the UI and without reading `navigator` during render (hydration). The copy is Spanish sentence case. It MUST NOT claim that anything is queued or synced: there is no queue in this branch.
- **S7 — CI guard.** A check MUST fail the pipeline when `/manifest.webmanifest` loses a required field, when `sw.js` stops being served, or when either capability tag disappears from a served route. It must run against a built app on a real HTTP response, the way the existing security-header step does, because a config-level unit test cannot see build-time loss.
- **S8 — Update flow.** A new service worker MUST NOT take over a running session silently. It waits; the app surfaces "Nueva versión disponible" with an explicit reload, and the operator decides when to swap code, because a POS can have an open cart. Choosing reload is the only path that activates the waiting worker.
- **S9 — Delivery debt.** Both build-time variables MUST be documented in `frontend/.env.example`, and the same-origin `/api` rewrite MUST live on its own branch so this feature can merge without changing production routing; the merge order is dependency-ordered and recorded.
- **S10 — Installed, not a tab.** The owner said: "quiero como todo cubierto, no quiero que si realmente se llega a notar que es un explorador". In standalone display the app MUST NOT rubber-band, MUST NOT pull-to-refresh, MUST NOT show a tap highlight, MUST NOT pop a long-press callout on chrome, MUST NOT double-tap-zoom, and MUST NOT let a rotation resize text. Text stays selectable where reading or copying matters, and inputs stay selectable everywhere.
- **S11 — Safe areas everywhere.** Every fixed or sticky surface — modal, toast stack, POS floating bar, POS cart drawer, expense and purchase-order action bars, sidebar, content column, auth pages — MUST pay back `env(safe-area-inset-*)`. The earlier work covered six surfaces; this closes the rest.
- **S12 — A cartridge line cannot be lost by a stray tap.** The owner said a quantity edit "me elimino un producto del carrito". Root cause found: the stepper is `min={0}` and `updateQuantity(0)` removes the line, so one extra tap on "−" deletes it, and the trash button is 28×28 px next to it. The stepper MUST NOT reach 0; removal MUST be undoable for a bounded window; the trash target MUST be at least 44×44 px and separated from the quantity control; a locked cart MUST stay locked.
- **S13 — Gestures do not eject the operator.** The owner said the back gesture "me sacó del login". In standalone mode, a left-edge back swipe at a root route or on the auth screens MUST NOT leave the app; inside the app it MUST keep working as normal navigation.

## Non-goals (parent-scoped, pending user confirmation)

- **Offline writes / offline POS.** Selling without connectivity needs backend idempotency keys (none exist today: `POST /sales` accepts no client key) and an explicit product decision on stock conflicts and on whether a client-computed price may override the server-owned price. Not in this branch.
- **Offline reads.** Persisting the React Query cache to IndexedDB is a separate work unit; it must be user/organization scoped before it can ship, because `X-Organization-Id` is multi-tenant state.
- **Same-origin API proxy.** The frontend calls `meperpos-api.up.railway.app` cross-site while `backend/src/auth/cookies.helper.ts` sets `SameSite=None; Secure` in production, and WebKit blocks third-party cookies "across the board". The httpOnly `refresh_token` therefore does not round-trip on WebKit, so an installed iOS app asks for login on every launch. Fixing it changes production API routing and needs a Vercel env change, so it is a separate decision — see T6.
- **Web push notifications, background sync.** Out of scope.

### Owner actions

**T26 content for `frontend/.env.example`.** The rules reject a write to this path, so paste this by hand:

```dotenv
# Backend API URL. Injected at BUILD TIME because of the NEXT_PUBLIC_ prefix, so
# changing it requires a new deployment.
#
# Two supported shapes, and the choice is a pair with BACKEND_ORIGIN below:
#
#   absolute  The browser calls the backend origin directly. Needs that origin to
#             allow this one (CORS) and to set its cookies for a cross-site
#             request. An installed iOS app loses the refresh cookie that way,
#             because WebKit blocks third-party cookies, so the app asks for a
#             login on every launch.
#
#   relative  "/api". The browser calls THIS origin and next.config.ts proxies to
#             BACKEND_ORIGIN, which makes the auth cookies first-party and lets an
#             installed iOS app stay logged in.
#
# Either way the value must include the /api suffix.
NEXT_PUBLIC_API_URL=https://your-backend.up.railway.app/api

# Origin the /api rewrite proxies to. Read at BUILD time by next.config.ts and
# never sent to the browser, so it is deliberately not a NEXT_PUBLIC_ value.
#
# Set it only together with a relative NEXT_PUBLIC_API_URL. Leave it unset in
# local development: a relative base with no proxy does not degrade, it ships an
# app that loads and then fails every request, so the build fails on purpose when
# exactly one of the two is configured. That guard ships with
# `feat/api-same-origin-proxy`, which is where the variables belong.
# BACKEND_ORIGIN=https://your-backend.up.railway.app
```

### Deployment variables (owner action)

These belong to `feat/api-same-origin-proxy`: that branch is where the rewrite and its build-time guard live, so it is also where a half-configured pair is caught.

Vercel → Project → Settings → Environment Variables, then **redeploy**: both are read at build time, so changing them without a new deployment does nothing.

| Variable | Value | Why |
| --- | --- | --- |
| `NEXT_PUBLIC_API_URL` | `/api` | Inlined into the client bundle. Relative, so the browser calls this origin. |
| `BACKEND_ORIGIN` | `https://meperpos-api.up.railway.app` | Read by `next.config.ts` to build the rewrite destination. Not a `NEXT_PUBLIC_` value, so it never reaches the browser. |

Setting only one of the two fails the build on purpose. Local development is unaffected: `.env.local` keeps an absolute URL, so no rewrite is registered.

**Proxy trust — corrected 2026-11-14.** This document used to say the backend still needed `app.set("trust proxy", 1)` on its own branch. That is false: `backend/src/common/proxy-trust.ts` already implements it, `applyProxyTrust` is wired in `backend/src/app-configuration.ts`, and `resolveTrustProxyHops` defaults to **one hop** with a forged-left-most-entry test in `proxy-trust.int.spec.ts`. What remains is a topology question, not missing code: with Vercel *and* Railway in front there are two hops, so a single trusted hop makes the backend attribute the request to Vercel's edge rather than the operator. Production would need `TRUST_PROXY_HOPS=2`; left at 1, throttling buckets are per-Vercel-IP for everyone behind that proxy.

**Unverified after deployment.** `ImageUpload` accepts files up to 5 MB, above Vercel's 4.5 MB Serverless Function payload limit. External rewrites are handled by the routing layer rather than a function, so the limit should not apply — but this has not been exercised, and one real logo upload through the proxy is the cheapest way to confirm it.
