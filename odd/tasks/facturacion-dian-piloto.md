- L29 CUFE input resolution implemented per section 11.2.2 (`cufe-input.ts`, 21 focused tests GREEN, ESLint clean). Two semantic facts from the annex change how the helper must be wired: `ValFac` is `LegalMonetaryTotal/LineExtensionAmount` (MeperPOS `Sale.subtotal`), not the tax base, and `ValTot` is `PayableAmount` (MeperPOS `Sale.total`), not the pre-discount total. Money is formatted by truncating the decimal string, never via `Number`, so `1500000.999` becomes `1500000.99` and never `1500001.00`; a differential test against the annex vector passes end to end through the resolver. Identifications are normalized by removing dots and spaces, and a dashed value such as `800.197.268-4` is REJECTED rather than silently hashed as `8001972684`, because the annex asks for the number without the check digit and MeperPOS cannot tell a 9-digit NIT with DV from a bare 10-digit one. `NumFac` concatenates prefix and consecutive with no separator, so the existing `SequenceService` formatted value `${prefix}-${number}` must not be reused directly. `FecFac`/`HorFac` are derived with an explicit `America/Bogota` zone and a constant `-05:00` offset, never local-time getters; a midnight-crossing case is pinned by a test. `environment` defaults to `'2'` (test) per S6 and any other runtime value is rejected at the resolver.
