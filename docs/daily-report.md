# Daily administrator report

`GET /api/reports/daily-report` returns JSON; `GET /api/reports/daily-report/pdf` downloads a PDF. Both require authentication, an administrator or owner role, and an organization scope. Super administrators must select an organization using the existing organization header or query convention. Responses are private and must not be cached. Each request captures its own cutoff; requesting JSON and PDF separately does not reproduce the same snapshot.

The report captures the current instant once and uses the corresponding Bogotá calendar day. The PDF displays the cutoff and sale timestamps in Bogotá local time. Sales are currently `COMPLETED` sales created between Bogotá midnight and the cutoff, following the existing sales dashboard's status convention; partial returns and cancellations are not reconstructed or netted. Sales amounts are recorded totals, not cash collections. Sale item amounts and customer/product names are included. Expense amounts include purchase-order-linked expenses and are not cash payments or profit. Money amounts use decimal arithmetic and are returned as fixed two-decimal strings in COP.

Low stock uses the existing physical-stock rule, excluding services and untracked products. Purchase alerts include PENDING and PARTIAL_RECEIVED orders. Loan alerts include OPEN monetary loans with a due date on or before the third Bogotá calendar day after the report day, including overdue loans. Balances reflect collection and reversal events. Employee names are not loaded; the PDF uses a neutral unavailable-counterparty label when no tenant-verified customer or supplier is present. Inventory loans have no due-date field and are not included. These alert selections are initial, reversible assumptions.

Expenses must be active and created no later than the cutoff. The existing expense API stores a date-only input as UTC midnight: the report interprets that value as its encoded calendar date. Other timestamps are included from Bogotá midnight through the cutoff, except the next UTC midnight, which is treated as the following date-only value. The database does not retain whether an exact UTC-midnight value originally came from a date-only input or a timestamp, so those two cases cannot be distinguished.

Queries run in a repeatable-read transaction. Current stock, names and statuses are mutable, and the transaction can begin after the captured cutoff: the report is a current view, not a historical reconstruction or a persisted snapshot. Date filtering does not reconstruct values subsequently changed or deleted. There is no payroll, scheduler, WhatsApp delivery or historical report endpoint in this feature.

PDF text uses jsPDF's standard font and normalizes text to NFC; extraction is tested with Colombian Spanish names and accents. Long lines wrap and continue across pages, but characters outside the font's supported repertoire may not render correctly. Reports contain customer and business data and should be handled accordingly.
